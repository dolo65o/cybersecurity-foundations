## Logs — Brief Overview

Logs are records of events generated by systems, applications, or devices.
Every action — a login, file access, network connection — gets recorded as a log entry.

### A Log Entry Typically Contains:
| Field | Description |
|-------|-------------|
| Timestamp | When the event occurred |
| Source | Which system/app generated it |
| Event Type | Category of the event |
| Severity | Info / Warning / Error / Critical |
| Description | What actually happened |

### Why Logs Matter in SOC:
- SIEM ingests logs from all sources and correlates them
- Analysts trace attacks by following the log trail
- Forensics uses logs to reconstruct what happened and when

> No logs = blind investigation

## Log Types & Usage

| Log Type | Purpose | Examples |
|----------|---------|---------|
| **System Logs** | OS activity troubleshooting | Startup/shutdown, driver loading, system errors, hardware events |
| **Security Logs** | Detect & investigate security incidents | Authentication, authorization, policy changes, user account changes, abnormal activity |
| **Application Logs** | App-specific events (interactive + background) | User interactions, app changes, updates, errors |
| **Audit Logs** | System changes + user events; compliance & security monitoring | Data access, system changes, user activity, policy enforcement |
| **Network Logs** | Inbound/outbound traffic; network troubleshooting + incident investigation | Incoming/outgoing traffic, network connections, firewall logs |
| **Access Logs** | Resource access tracking | Webserver access, DB access, application access, API access |

> Other log types exist depending on the application/service.

---

### Practical Example
> Need to investigate successful logins from yesterday on Windows?
> → Check **Security Logs** only — no need to scan all logs

## Web Server Log Analysis — Linux CLI

### Apache Access Log Location
```
/var/log/apache2/access.log
```

### Log Entry Fields

| Field | Example | Description |
|-------|---------|-------------|
| **IP Address** | `172.16.0.1` | Who made the request |
| **Timestamp** | `[06/Jun/2024:13:58:44]` | When the request was made |
| **HTTP Method** | `GET` | Action to perform |
| **URL** | `/products` | Requested resource |
| **Status Code** | `200` / `404` / `500` | Server response result |
| **User-Agent** | `Mozilla/5.0...` | Browser + OS info of requester |

---

### CLI Tools for Log Analysis

#### `cat` — Display / Combine logs
```bash
# View log
cat access.log

# Combine two logs into one
cat access1.log access2.log > combined_access.log
```

#### `grep` — Search for strings/patterns
```bash
# Find all entries from a specific IP
grep "192.168.1.1" access.log
```

#### `less` — Page-by-page viewing
```bash
less access.log
```

| Key | Action |
|-----|--------|
| `Space` | Next page |
| `b` | Previous page |
| `/pattern` | Search for pattern |
| `n` | Next occurrence |
| `N` | Previous occurrence |
